Pocket-Check (plugin) - Changelog
=================================
openFPGA Pocket updater plugin. Scans the Pocket SD card (Assets, Cores,
Platforms, Presets) for missing / empty / orphaned / mismatched ROMs and
instance .json files. Never changes games, cores or settings; it only writes its
own report / ignore list files.

v0.2.1 - 2026-11-07
  - Fixed: the report and ignore list were being written to the updater's private
    "host" folder on the computer (v0.2.0), but pupdate runs from the SD card and
    nothing should be written to the computer. They are now written to the plugin's
    folder on the SD card, \plugins\OngoGablogian.pocket-check-plugin\, with the SD
    card root as the only fallback. The host folder is never written to
  - An ignore list left in the SD card root (v0.1.2) or in the host folder
    (v0.1.0, v0.1.1, v0.2.0) is copied into the plugin's folder on the SD card the
    first time this version runs (the old copy is left alone)
  - The log says "the plugin's folder on the SD card", "the SD card root" or "the
    updater's private plugin folder on the computer" for each file

v0.2.0 - 2026-11-07
  - The report, ignore list and optional manifest are now kept in the plugin's own
    folder on the computer (the "host" folder; in pupdate
    \plugins\OngoGablogian.pocket-check-plugin\) instead of the root of the SD card.
    The SD card root is only a fallback if there is no plugin folder or it can't be
    written to
  - An ignore list found in the SD card root (created by v0.1.2) is copied to the
    plugin's folder the first time this version runs (the old copy is left alone)
  - Menu titles show the plugin version (to tell which build is running)

v0.1.2 - 2026-11-07
  - Pocket-Check-Ignore.txt, Pocket-Check-Report.txt (and the optional
    Pocket-Check-Manifest.json) now live in the root of the SD card instead of the
    plugin's private "host" folder, which is hidden somewhere in the updater app's
    data and hard to find. The host folder is only a fallback if the card can't be
    written to
  - An ignore list found in the host folder (created by v0.1.0 / v0.1.1) is copied to the
    SD card root the first time this version runs
  - The log now says where each file was written ("the SD card root (...)" or
    "the plugin's host folder (...)") and reports clearly if a write fails

v0.1.1 - 2026-11-07
  - Fixed a crash while scanning ("panicked ... SystemTimeError(11644473600s)" in
    wasi-common): the host app panics when a file's timestamp is before 1970 (e.g.
    1601-01-01 on files written by devices without a clock) and the plugin asked
    it for that file's details. The plugin no longer asks for file metadata at all:
    folder/file type comes from the directory listing, sizes from seeking to the
    end of the file, and files are read in chunks instead of with fs::read

v0.1.0 - 2026-11-07
  - First version: Rust port of Pocket-Check.py v0.6.1 for
    https://github.com/openfpga-library/pocket-plugin
  - Same checks and report as the script: cores, platforms, presets, instance
    JSONs (missing / empty / orphan ROMs, case mismatches, bad JSON), Analogizer /
    jtpatreon / coinopkey / .sav / "._*" skipping, ignore list, unified
    "== Ignored files (N) ==" section
  - Menu instead of command-line options:
      Scan the whole card / Scan one platform... (id or glob, comma separated)
      Default / Also check .sav / Also check Analogizer/CRT / Check both
  - Files: Pocket-Check-Ignore.txt (created with instructions on first run),
    Pocket-Check-Report.txt (rewritten on every run), optional
    Pocket-Check-Manifest.json ({ "file.rom": {"size": 1234} }); v0.1.0 kept
    them in the plugin's host folder, v0.1.2 moved them to the SD card root
  - Long reports are summarised in the log (counts per category); the full
    text is always in Pocket-Check-Report.txt

  Differences from the Python script
  - No --crc / crc32 manifest entries (only "size" is checked), no --rom-ext,
    --no-orphans, --no-cores, --out, --no-report
  - Ignore-list wildcards support * and ? only (no [abc] sets)
  - Old Ignore-Cores.txt / ignore_cores.txt files are not carried over
